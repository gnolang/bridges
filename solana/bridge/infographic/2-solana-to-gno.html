both fingerprints sit in finalized blocks, so the only way the sum matches is a complete, honest list of changes (unless someone breaks the hash).
Why no single-account proof: a total can be checked only by re-adding everything that changed. That is the lattice-delta proof: reveal every changed account, old and new, and show the differences add up.
Griefing: anyone can bloat a block's change list (dust to huge accounts) — ≈4–9 SOL a day for every block, under a cent for one block by a producer. A griefed block's burn is credited by GovDAO vote instead.
The roster: who the validators are each epoch is committed nowhere until SIMD-0511; until then the signers vouch for it, once per epoch.
THE PROVER
a node that keeps every account's old and new state for each block — fed with N's changed accounts and the certificate. The operator's GPU box first; anyone's such node; or a hired prover network.
runs the ZK program:
✓ certificate valid for the epoch's roster
✓ block id → footer → bank hash
✓ every changed account adds up
✓ the burn record is among them
a Groth16 proof — a few hundred bytes that say "the whole check passed". 10–90 min of GPU, $1–6 a block.
The prover is never trusted: a wrong or missing fact makes the proof fail. A missing prover only delays.
the relayer — a job on the operator's monitor box, anyone may run it — carries the proof + the burn record to gno.land
the verifier realm (on gno.land)
one native call, PairingCheck (≈1.8M gas), verifies the Groth16 proof. Inside that proof:
✓ Solana's certificate over block N's id
✓ block id → footer → bank hash of N
✓ every changed account adds up to the fingerprint change
✓ the burn record: our mailbox, our token program, 100 GNOT → you
what it believes without proof: the epoch's roster (the signers vouch) and that Solana's ≥ 20% safety bound holds.
If the check fails, nothing happens. No person is asked.
