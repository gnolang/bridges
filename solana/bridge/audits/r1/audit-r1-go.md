# Audit 6, round 1 — the Go side as built (bridge/, branch `bridge` HEAD be69e1c, 2026-10-13)

Read: PLAN.md §5.5–§5.9, §6.1–§6.3; M3-NOTES.md; every Go file under agent/, sol/, gno/, gnolight/, hl/, cmd/hlbridge, cmd/hlwatch, cmd/hlsol, cmd/hlkey; local/e2e.sh; tools/. `go test -race ./...` run once (green). Read-only otherwise.

## Findings

### G1 — high — a stale proof stage is resumed, never rebuilt; messages strand after any set change
agent/stage.go:19–72 (resume skips the init and every filled chunk, compares nothing); agent/relayer_sol.go:355–357 (stage keyed by submitter + sha256(message)), 403–412 (a failed `process` leaves the stage).
Scenario: a route message is staged by the ring, or by a header of the old set, seconds before a validator change; its `process` fails once (a dead RPC). On the retry the plan is new — the ring is cleared, a Reemit gave a fresh leaf — but the PDA is the same, `driveStage` sees it exists, skips the StageInit and the leaf, and `process` reads the old ring hash and proof: NotInRing / WrongSet / ProofMismatch, deterministic, parked after three, hourly for ever. Nothing in the Go side or hlsol ever sends StageClose for it; the rent stays and the message waits for a human's hand-made transaction. The e2e stages every message exactly once, so it cannot see this.
Fix: after `ParseStage`, compare Kind, ByRing/RingHash, HeaderHash, Proof and LeafLen with the plan's StageInit; on any difference send StageCloseIx and start from the init. In `deliverOne`, close the stage when `process` fails deterministically. Add `hlsol close-stage`.

### G2 — high — proofs are staged while the pausable ISM refuses; the float drains into rent and the unpause cannot be delivered
agent/relayer_sol.go:285–357 (staging before `process`), 141–256 (no read of the pausable ISM's flags or the client's quarantine; `grep readPausable|Quarantine agent/relayer*.go` is empty).
Scenario: every validator vote on gno.land opens a 7-day quarantine; a guardian or watch flag pauses likewise. The relayer still stages each gno → Solana message in full (two or three transactions, ≈0.01 SOL of rent locked each) before `process` answers Quarantine/Paused — deterministic, three failures, parked, resumed hourly. At 50 transfers a day the 2 SOL float is locked in stages within days; later stagings fail for lamports and park too; the runway alarm fires; hundreds of `parked:` alarms repeat hourly. An unpause decision is delivered by the same key, so the pause that drains the float blocks the lever that ends it.
Fix: before staging a route message read `readPausable` (any flag) and `clientState.Head.QuarantineEnd`; while either stands, note "deliveries paused" and attempt no route delivery (decisions still go, through the client). Order the pass so decisions are tried before routes.

### G3 — high — "the client is past the chain" flags both Solana objects on the first poll after the own node lags
agent/monitor.go:245–261; agent/chain.go:50–66 (`headAfter` returns a stale head after 15 s); `gno.Head.CatchingUp` is parsed and never read.
Scenario: the updater keeps T within minutes of the chain's head. The monitor's own node reboots or upgrades and comes back catching up (an hour behind takes a minute or two): the first poll gets `Status` with an old head, `headAfter` gives up after 15 s, `head.Height < T`, and `flagSolana("header:mismatch", …, adminToo)` sets the watch key's flag on the pausable ISM and the admin program at once — no persistence, no second source, no CatchingUp check. Deliveries stop and 7-day decisions defer until an unpause decision or the holder's hand clears it. M3-NOTES promises "a flag if it persists"; the signer's same reading uses an allowance and a second source (judgeAhead).
Fix: treat `CatchingUp`, a head not after the snapshot, or a head older than `ownLagAfter` as no verdict (alarm `gno:own`); judge past-the-chain as the signer does (allowance + `gno.sources[0]`'s head) and pass it through `persist(…, cutFailAfter)` before flagging.

### G4 — high — the taken-number report fires falsely at the backup relayer on every decision
agent/relayer_sol.go:156–211 (admin state read at confirmed, `ids[seq]` only from this pass, Done copies skipped before counting), 260–282 (`pastDecision`); agent/chain.go:592–598 (`solDelivered` at finalized).
Scenario: the primary delivers decision N. Three seconds later the backup reads LastSeq = N (confirmed) while N's processed-message account is not yet finalized (~13 s): gate "past", no copy of N processed, `Done = "taken"`, and the alarm "decision N cannot be delivered: another decision has already taken its number; r/hlgov's sync sequence moves the counter past it and the proposal is re-made". This happens for every decision in a two-relayer deployment, and on the primary for any re-dispatched copy of a number delivered in an earlier pass. GovDAO acting on it wastes a vote or mis-syncs the counter (kind 10 lands only above the high-water mark).
Fix: read the admin state and the processed-message record at one commitment; keep seq → ids across passes in the state and consult `Done`; report "taken" only when the record is still absent at finalized on a second pass.

### G5 — medium — the status endpoints encode the loop's live maps outside the lock; the signer's is public and a flood can crash it
agent/signer.go:496–521 (`Status` returns `s.state.SolCursors` itself; the handler encodes after the lock is released), 359–360 (`index()` writes the cursor map with no lock), 403–407; agent/relayer.go:620–656; agent/monitor.go:768–791 (the same shape, loopback by convention).
Scenario: `/v1/status` shares the signer's public signature listener (§5.7). Anyone flooding it makes `json.Encode` iterate `SolCursors` while the run loop writes it; when the two overlap Go's runtime aborts the process ("concurrent map iteration and map write"). Under systemd the signer restarts, loses its in-memory halt (the stored signature still refuses the conflict), waits for a first verdict, and dies again on the next overlap; three signers in a crash loop stop the Solana → gno direction for as long as the flood lasts. `go test -race` is green only because no test reads the status concurrently.
Fix: in every `Status()` build deep copies of maps and slices while holding the mutex (or marshal under the lock); take `s.mu` around the cursor write in `index()`; serve `/v1/status` on a loopback listener separate from the public `/v1/sol/`.

### G6 — medium — the monitor's and hlwatch's Solana-side flags rest on one provider
agent/monitor_sol.go:61 (`Record.Sync(m.sol[0])`), 125 and 138 (`foreignDecisions`), 188 (`deliveriesPaused`); agent/monitor.go:525 (`readSends`); agent/views_sol.go:219, 296, 307, 313, 321, 338 (hlwatch's record, pausable, admin, pending decisions, foreign findings).
Scenario: only the supplies and the client's head must agree across both providers. One lying provider can serve a StageInit the own node never saw (`header:mismatch`), an admin state with LastSeq past r/hlgov's (`decision:foreign`), or a phantom flag on the pausable ISM (`sends` on every gno route): each a flag on the pausable ISM and the admin program through the watch key, cleared only by an unpause decision or the holder's hand — a pause lever for a provider, which §5.6 and §5.9 ("two providers of its own", "from two agreeing providers") rule out. hlwatch prints the same one-provider readings to every guardian.
Fix: read the record's transactions, the admin and pausable accounts, the pending decisions and the processed-message records from both providers and require equal bytes (as `readClientBoth` does) before any flag; on disagreement alarm `solana:providers` and skip that rule for the poll. In hlwatch, mark one-provider sections as unconfirmed.

### G7 — medium — a signer keeps signing on a verdict of any age, and a halted signer re-fetches its backlog every round
agent/signer.go:134–139 and 273–282 (`unverified` leaves `verified` true), 171–194 (a snapshot disagreement or outage is "no verdict"), 336–365 (`index()` scans provider 1 from the signing cursor, which never moves while halted).
Scenario: (a) a provider that misreports a supply, or an outage of either, makes every round "no verdict" for hours or days; the refusal rule is never re-evaluated and the signer signs on (per-dispatch agreement still holds, but a forged credit after that moment is never seen) — §5.6 says one bad provider halts at most two signers, not that it blinds them. (b) While halted, each round re-fetches every unsigned dispatch (two RPC calls each); hundreds of burns waiting on a halt trip the provider's rate limit, `index()` errors, the round has no verdict, and the halt can never clear — even after the void that closes the identity.
Fix: stamp each verdict; after an hour without a fresh held cut set `halted = "no verdict for an hour"` until one returns. Give `index()` its own cursor per provider (`SYM#0i`) and keep unsigned dispatches in memory, so a halt costs no re-fetch.

### G8 — medium — every relayer tick is O(backlog) with a block_results fetch per undelivered message, and one error aborts the pass; the monitor's sends walk likewise
agent/relayer.go:559–615 (`reemits`: a render, a Solana read and `BlockResults` per message, every tick), agent/relayer_sol.go:58–77 (`r.leafs` written, never read — `grep "r.leafs"`), 141–256 (`return err` on the first failed read); agent/monitor.go:566–608 (`readSends` per unprocessed send, aborting on the first error).
Scenario: a quarantine or a flag lets the backlog grow to hundreds (3,500 at 500 a day). Each 3 s tick then makes thousands of calls against the own node and the provider; a rate limit or one bad block aborts the pass at its first error, so nothing later in the queue is tried; the monitor's poll aborts in `readSends` and gives no identity verdict for the whole pause; the state file (`Done` keeps every nonce ever) is rewritten every tick. The load is self-inflicted exactly when the bridge is paused.
Fix: read the leaf cache in `leafAt`; run `reemits` only for messages whose attempt is due, or once a minute; skip (not abort) a message whose read fails; keep only `Done` entries at or past `GnoNext`; make `readSends` continue past one failed message.

### G9 — medium — the header record ignores inner instructions; a kind-11 reset leaves a permanent "unfillable gap" flag
agent/record.go:200–232 (`transactionInstructions` reads `tx.Message.Instructions` only; `Meta.InnerInstructions` never), 100–145 (`Fold` expects a Reset as variant 7 of the client program); sol/admin.go:186–187 (kind 11 runs as the admin program's Execute calling the client by CPI).
Scenario: GovDAO or the validators reset the client (kind 11) at the end of a recovery. The client counts the reset's trusted header in its record; the monitor and hlwatch, reading only top-level instructions, never fold it. From then on `Consistent` says "an unfillable gap: N entries rebuilt, the client counts N+1", and after two minutes the monitor flags the pausable ISM and the admin program (`header:gap`) — at the moment the bridge is being restarted — while every guardian's hlwatch shows the record inconsistent. The e2e never resets, so the Reset entry's shape was never checked against the program either.
Fix: in `transactionInstructions` append each top-level instruction's inner instructions (`res.Meta.InnerInstructions`, resolved through the same key table) in execution order; add a kind-11 step to the e2e that checks `Consistent` afterwards.

### G10 — medium — the audit prints the chain's header beside the client's trusted hash but never compares them; the setup only warns on an hour-old header
cmd/hlsol/audit.go:312–323 (`a.note("the chain's header %d hashes to %x", …)` beside the set-hash `line`), 239–240 (the trusted hash in another note, eight bytes); cmd/hlsol/setup.go:432–434 (`WARNING trusted header … old`).
Scenario: the audit's PASS is the setup's done condition and the launch gate (§5.8, §5.9). A client initialised from a forked or forged header at the trusted height — a node that lied to `hlsol setup`, or a wrong `-gno-rpc` — passes every line "ok": the set hash matches `/validators` (the set is the real one), and the block hash is printed for a member to compare eight bytes by eye across two notes. A trusted header older than an hour (§6.1's rule) is a warning the setup runs past.
Fix: add `a.line(blk.Hash == head.TrustedHash, "the client's trusted hash against /block?height=%d …")` over the full hashes; make an hour-old trusted header a refusal in `trustedHeader` unless `-allow-old-header` is given.

### G11 — low — decisions are never re-emitted by the relayer, although its own delivery asks for it
agent/relayer.go:570–576 (`reemits` skips every message whose recipient is not a token route); agent/relayer_sol.go:332–334 ("a Reemit is asked" for a decision too).
Scenario: a decision from r/hlgov is dispatched in the minute before a validator change executes (or while the updater is down); the client follows the change before header h+1 is accepted. `deliverOne` now answers "signed by a set that is not the client's current one; a Reemit is asked" every tick, but `reemits` never looks at it. The decision waits for ever: the executor cannot see it, hlwatch shows r/hlgov's counter ahead of the admin program's ("a foreign decision took a number, or GovDAO's was lost"), and only a human's `Reemit(nonce)` moves it. §5.7 makes Reemit the relayer's job for "any message that needs it".
Fix: in `reemits`, treat `classify(msg) == kindDecision` like a route message; the set-change, leaf-size and unbuildable-block reasons are the same.

### G12 — low — state and key hygiene: no fsync, no key mode check, identical providers, no per-call deadlines, the watch key's re-assertion drain
agent/chain.go:616–626 (rename without fsync); agent/signer.go:449–464 (an unparseable `sol/<nonce>.json` is a nonce conflict); hl/keys_validator.go:37 and every `PrivateKeyFromSolanaKeygenFile` (no mode check); agent/config.go:267–274 (the same URL twice passes); sol/sol.go:305 (`rpc.New`: solana-go's five-minute default timeout) and gno/gno.go:340 (gnokey with no deadline); agent/monitor_sol.go:240–263 (a flag transaction every poll while a condition stands); agent/relayer.go:225–228 (`forget` never clears `parked:`).
Scenario: a power loss leaves a zero-length state file (every machine refuses to start until a human deletes it) or a zero-length signature file (a sticky "nonce conflict" halt). A deployment config naming one provider twice makes "two providers agree" vacuous with only a log line. One stalled endpoint holds a signer's or monitor's loop for five minutes per call. A standing break re-asserts the Solana flag every 10 s at 5,000 lamports: the watch key's 0.05 SOL lasts ~28 h, no runway watches it, and after that the "fresh slot" an unpause reads stops being fresh.
Fix: fsync the temp file and its directory before rename; name corruption as corruption; refuse key files with mode wider than 0600; refuse identical providers unless `allowHTTP`; wrap each RPC and gnokey call in a context with a deadline (30 s / 90 s); re-assert at most once a minute and watch the watch keys; clear `parked:` in `forget`.

## Checked and held

- Keys: the signer's ed25519 seed, the relayer's and updater's SOL keys, the watch keys and the gas-only gnokey name are read from files and never logged or sent (public keys only); `hlkey new` writes 0600 and refuses to overwrite; `hlsol keygen` is marked local-only; the deployer's key signs deploys and inits only and the audit prints its balance.
- Transport: signer fetches refuse plain http unless loopback or `allowHTTP`, verify TLS by default, cap the body at 1 MB with a 10 s timeout; gno RPC reads cap at 8 MB with 30 s; `/v1/sol/<nonce>` parses the nonce as an integer (no path traversal); webhook posts are bounded goroutines with a 10 s deadline.
- Provider agreement where it matters most: supplies and the client's head must match across both providers; a dispatch is signed only when provider 2 shows the same message bytes in the mailbox's own dispatched-message account (owner, tag, slot and nonce checked, logs never trusted); the no-shared-pair rule is enforced by `hlbridge providers`.
- The ordered cut: snapshot first, the own node's block after it, every render pinned at that height, burns credited above the snapshot's slot break the order; in-flight only shortens the right side; `Identity`, `Cut.Holds`, `JudgeSources` and `judgeAhead` are pure and tested.
- The signers' rules: once per message, the nonce conflict sticky and served, no signature before a first verdict, the tight refusal rule, the stop when T exceeds both heads by the allowance, clearing on a held cut at or above T.
- The relayer: exactly the rule's signatures, each verified against hlmailbox's key; `Claim(20)` with doubling backoff; `Execute(id)` by block time; three deterministic failures park, hourly retries; `Reemit` once per reason for routes; `HandleAccounts` from the simulation with signer and payer metas refused; the admin program's metas checked against v27's; cancels capped at 16 pairs.
- The executor: the floor rule, NotMature/Deferred as waits, CancelSpent/LayoutFixed never retried, NeedsExtend one step, cancelled decisions closed, the backup 60 s later.
- The updater: its own key and float; the announcing header found by binary search with a linear fallback and verified against NextValidatorsHash; stages resumed from the chain; the lag alarm at an hour; a trusted header that itself announces is reported, not followed.
- The monitors' flags: credits and payouts (never sends) on a break or a diverted credit, sends alone while deliveries are paused and cleared after, never a void, the third-source rule never touches payouts, own-node-odd downgrades the identity rules to alarms, one webhook post per key per hour.
- hlwatch: refuses without `-node` and two providers; pre-armed by the executor's realm, never the title; the forged verdict needs both providers' indexes empty and a broken identity; the one-stroke flag checks the seat on both chains.
- hlsol setup: §5.8's binding order, every step read from the chain first, buffers closed before a deploy, the burn last, `finish_setup` self-checking, done = the audit's PASS; the e2e's second run sends nothing; the audit prints every RPC call as a curl line.
- `go test -race ./...` green. The e2e never exercises: a provider disagreement (one URL twice), a backup relayer, a validator change or quarantine, a flag, hold, dip or unpause, a parked or re-emitted message, a crash mid-stage, a recovery or reset, a leaf over 8 KB, TLS, the Solana watch key flagging, a matured decision executing.

## Verdict

Nothing critical: the chains hold the money and the Go side decides nothing a lying party could cash. Four highs, all liveness or false-flag failures the e2e cannot see: a stale proof stage strands messages after every set change, staging under a pause drains the float the unpause needs, a catching-up node flags both Solana objects, and a backup relayer reports every decision "taken". Six mediums tighten the two-provider rule, the no-verdict semantics and the record. Fold G1–G9 before devnet; round two should add a backup relayer, a set change and a provider disagreement to the e2e.
