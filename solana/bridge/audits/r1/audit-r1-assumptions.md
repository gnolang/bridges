## FALSE and UNVERIFIED, expanded (the smallest change for each)

**F1 (high) — `ExtendProgramChecked` does not exist on mainnet.** `sol-util/src/loader.rs:95-97` encodes loader instruction 9 and `admin-program/src/processor.rs:458` sends it for every 10 KB growth step. Agave v4.3.0 — what mainnet reports — handles instructions 0–7 plus `ExtendProgram` (index 6) and nothing else; v3.0.14 had the checked form behind `enable_extend_program_checked`, which was abandoned with SIMD-0164 (the feature id now reads "Wi11BeDe1eted"; the account is absent on all three clusters). The suite passed because program-test 3.1.12 still carried it. On mainnet every `ExtendForUpgrade` fails with `InvalidInstructionData`, so a growing kind-8 upgrade can never land. Smallest change: send `ExtendProgram` (index 6; accounts programdata, program, system, payer) — permissionless, the authority need not sign, the executor pays — and keep the one-per-block step; add a program-test with `enable_extend_program_checked` deactivated; re-measure the step's CU.

**F2 (medium) — an executor error is not "denied for good".** The deployed proxy (`proxy.gno:243-269`) re-panics an executor's error under `ExecuteProposal`, so the deadline error reverts the transaction exactly as a panic does and the proposal stays accepted-and-unexecuted forever; only `ExecuteOrRejectProposal` persists the denial. The plan's deadline still holds (nothing executes after 14 days), but a dead `Launch` or any dead builder proposal stays listed as pre-armed in `hlwatch` until someone calls the rejecting entry point. Smallest change: §2 and §5.3 say "denied for good once anyone calls `ExecuteOrRejectProposal`"; the relayer's `Execute` loop and `hlwatch` call it for a proposal past its deadline; M1-NOTES' "GovDAO then denies the proposal for good" is corrected.

**F3 (medium) — tmkms signs no bare digest.** tmkms (0.15.0, 2025-11) serves SignVote, SignProposal and Celestia's SignRawBytes, whose signature is over `"COMET::RAW_BYTES::SIGN" ‖ protobuf(request)`, never the 32 bytes the admin program verifies; gnokms signs only votes and proposals; a Ledger-held key signs nothing else at all. A YubiHSM signs any bytes for whoever holds its authentication key (tmkms's own `yubihsm test` does), and a softsign file is readable. Smallest change: §11.10 names the helper per backend — softsign: read the key file; YubiHSM: an HSM-level `sign_ed25519` with the auth key, outside the privval service; Ledger: cannot sign, so such a validator's assent is "unable" — and the assent letter asks each validator which backend holds the key (U4). Alternative (code): accept tmkms's raw-bytes envelope as a second digest form in `recovery::verify`.

**F4 (low) — namespaces.** r/sys/names as deployed grants a namespace to the address itself or to a name registered in r/sys/users (enforcement is on; "moul" resolves, "jae" does not). The bridge's paths are address-namespaced, so nothing moves; §13's sentence becomes "an address's own namespace, or a name registered to it".

## Verdict

The trust statement's foundations hold as verified facts, not recollections: tm2's 16-leaf header hash, the 110-byte sign bytes, the power-weighted commit rule and the A/A+1/A+2 timing reproduce on live gnoland-1 blocks; the validator set, the GovDAO members, the three proposals, the deployed GovDAO (v1.2.0's examples, byte for byte), r/sys/validators' events, the keeper's `private` rule, the storage and gas prices, Solana's rent, fees, loader, precompile and clock, Hyperlane's mainnet bytes and Alpenglow's testnet activation all check out. Three assumptions are false with consequences: the admin program's growth step uses a loader instruction mainnet does not have (high; one instruction swap), an executor error does not deny a proposal unless `ExecuteOrRejectProposal` is called (medium; wording plus one call), and no KMS signs the recovery digest through the privval protocol (medium; §11.10 must name an HSM-level helper and a Ledger validator cannot sign). Eight items stay unverified, each with its check named; none blocks the next round.
